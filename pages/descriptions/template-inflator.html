Features

  • Generate source, test, and resource files from templates
  • Support shared constants and per-variant values
  • Write output files to configurable directories
  • Integrate with these Maven build phases:
    • generate-sources
    • generate-test-sources
    • generate-resources
    • generate-test-resources

For each variant, the plugin resolves placeholders in controller values and templates, then generates the corresponding output file.

Getting Started

  1. Download
    • template-inflator-2.0.0.jar
    • template-inflator-2.0.0.pom
  2. open the terminal and navigate into your download folder, then run:
    mvn install:install-file -Dfile=template-inflator-2.0.0.jar -DpomFile=template-inflator-2.0.0.pom

How it works

TemplateInflator reads a controller file, combines each variant with each file definition, resolves placeholders using constants first and variant values second, then writes the rendered template to the configured output path.

  1. Read shared constants
    constants defines key-value pairs available to all variants and templates.
  2. Build variant/file combinations
    variants defines one or more sets of values.
    files defines the templates to use and where the output should be written to.
    TemplateInflator combines every variant with every file.
  3. Resolve placeholders and generate output
    For each variant/file combination:
    • all ${key} placeholders in variants and files are first replaced using values from constants
    • then ${key} placeholdes from the selected variant are applied
    • the referenced template is loaded
    • placeholders in the template are replaced using the same order:
      1. constants
      2. varian values
    • the final content is written to the file defined by dest and ext

Controller schema

FieldDescription
constants Key-value pairs shared by all variants
variants One or more objects containing per-variant values
files Tenpokate definitions to render

Each object in files must define:

FieldDescription
dest Output path, starting with Java package name, followed by /, followed by the output file name
ext Extension of the generated file
name Template file name, including its extension

Placeholder resolution order

Placeholders are resolved in this order:
  1. constants
  2. variant values

If a key is defined in both, the constant value is applied. If a placeholder cannot be resolved, it remains unchanged as plain text.

If a file already exists, it will be overwritten. Do not use a normal source folder as the output directory.

Generated files can be written to directories such as:

  • src/main/generated for main sources
  • src/test/generated for test sources
